# Observation Capsules

Observation capsules preserve one recon collection as a caller-owned,
integrity-bound JSON artifact. They let an operator replay the recorded state
without network access and compare two collections without treating every
rendered-output difference as a public fact change.

The capsule contract is separate from the stable `recon <domain> --json`
contract. The lookup JSON remains the authoritative runtime interface. Capsule
schema v1 is defined by
[`observation-capsule-schema.json`](observation-capsule-schema.json), and the
wheel ships a byte-identical copy as
`recon_tool/data/observation-capsule-schema.json`.

## Capture

```bash
recon capsule capture example.com --output example-capsule.json
```

The command performs the ordinary live public-metadata collection. DNS
infrastructure may observe DNS traffic, and the standards-defined MTA-STS
request remains the only default request to a target-owned application host.
Certificate-transparency collection is enabled unless `--no-ct` is passed.
Google CSE and BIMI certificate probes remain off unless `--direct-probes` is
explicitly passed.

Useful controls:

```bash
recon capsule capture example.com \
  --output example-west.json \
  --vantage resolver-west \
  --no-ct \
  --timeout 60
```

`--vantage` is a caller-chosen label. recon does not infer a resolver address,
network location, or organization identity. The default is `caller-local`.
The output path is never replaced unless `--force` is explicit. Writes use a
same-directory temporary file and an atomic replacement. Newly reserved files
use owner-only mode where the operating system supports it.

The capsule contains:

- the collection start, end, and frozen evaluation `as_of` timestamps;
- the CT and direct-probe choices, timeout, vantage label, and cache
  provenance;
- per-source opportunity states and the shared observation window;
- retained DNS records and normalized source scalars, each with a
  content-derived stable fact identifier;
- a normalized internal snapshot and the recorded stable lookup rendering;
- stable signal rule identifiers instead of reconstructed display prose;
- recon, normalizer, catalog, and model versions or digests;
- a deterministic SHA-256 content digest generated by recon.

The artifact deliberately does not retain complete HTTP response bodies. It
keeps the bounded normalized state and retained evidence that recon already
uses. This minimizes content while preserving the source and interpretation
boundary available in the current resolver.

## Replay

```bash
recon capsule replay example-capsule.json
recon capsule replay example-capsule.json --json
recon capsule replay example-capsule.json --as-of 2026-08-14T12:00:00Z --json
```

Replay verifies the outer content digest, every fact digest, the normalized
snapshot, and the recorded rendering digest. It then renders the recorded
normalized state using the installed recon version. It performs no DNS, HTTP,
certificate-transparency, or identity request.

The replay record includes both recorded and current interpretation contexts.
`interpretation_context_match: false` means the installed recon, normalizer,
catalog, or model does not match the one recorded in the capsule. It does not
mean that either interpretation is correct or incorrect.

An explicit `--as-of` changes the time-evaluation context only. Capsule schema
v1 emits an empty `freshness_changes` array because recon has not assigned one
universal freshness rule to heterogeneous public metadata. A later stable claim
family may add concrete freshness transitions when it has an absolute,
replayable predicate.

## Compare

```bash
recon capsule compare example-before.json example-after.json
recon capsule compare example-before.json example-after.json --json
```

The result has four independent sections:

| Section | Meaning |
|---|---|
| `observation` | Retained normalized facts changed under comparable source opportunities. Every confirmed fact names its source role and endpoint observation window. |
| `collection_regime` | Options, vantage, cache provenance, or source opportunity state changed. |
| `time_evaluation` | The explicit evaluation `as_of` changed. This is not new public evidence. |
| `interpretation` | The recon version, normalizer, catalog, model, or same-facts rendered result changed. |

Source roles in `partial` or `unavailable` state are conservative comparison
barriers. If the earlier role was unavailable, recon withholds additions. If
the later role was unavailable, recon withholds removals. The JSON report lists
every withheld role in `observation.suppressed_source_roles`.

The current role boundary follows the resolver's source results. It can be
coarser than an individual DNS channel, so suppression may withhold a valid
change rather than overstate one. A future channel-level capsule revision must
remain backward compatible or use a new capsule schema version.

## Integrity, privacy, and retention

The content digest detects modification, but it is not a digital signature and
does not authenticate who collected the data. If provenance across trust
boundaries matters, sign the complete capsule with an external signing system
and retain that system's identity and timestamp evidence separately.

Capsules may contain public DNS values, verification tokens, tenant identifiers,
related domains, and collection metadata. Publicly observable does not mean
context-free or harmless to redistribute. Protect the file according to the
operator's data policy, review it before sharing, and do not commit real-target
capsules to this repository.

recon does not upload, schedule, monitor, or retain capsules. Longitudinal
storage and automated monitoring require a separate privacy, threat-model, and
architecture decision.

## OKF and Agent Plugins boundary

Open Knowledge Format v0.2 is not emitted. There is no named consumer, and
mapping collection success to OKF `verified`, lookup time to `generated.at`, or
generic TTLs to `stale_after` would overstate those fields. ADR-0014 records the
deferral and the gate for any future additive projection.

Agent Plugins v1.0.0 remains a Working Draft for portable skill and MCP package
layout. It does not define this evidence artifact. Capsule support makes no
Agent Plugins conformance claim and does not alter MCP wire behavior.
