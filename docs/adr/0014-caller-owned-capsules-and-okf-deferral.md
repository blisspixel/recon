# ADR-0014: Use caller-owned JSON capsules and defer an OKF projection

- **Status:** Accepted
- **Date:** 2026-08-13

## Context

The legacy delta path compares two rendered lookup snapshots. A changed
catalog, normalizer, software version, evaluation time, cache path, resolver
vantage, collection option, or unavailable source can change that output even
when the public observations did not change. The v2.13 roadmap therefore calls
for a replayable, caller-owned observation artifact and a comparison that keeps
observation, collection-regime, time-evaluation, and interpretation changes
separate.

Open Knowledge Format v0.2 is a minimal directory of Markdown files with YAML
frontmatter. It adds optional provenance, trust, lifecycle, freshness, and
attestation fields. It is designed to complement rather than replace
domain-specific schemas. No current recon consumer has requested an OKF bundle,
and several OKF fields would be easy to overstate:

- an OKF `verified` event means that an actor confirmed content against its
  source or resource; a successful public lookup is not that confirmation;
- recon fingerprint `verified` is instead a scalar rule-review date. Fingerprint
  `confidence` is a domain-specific evidence-strength tier, and aggregate round
  counts measure catalog coverage. None maps directly to OKF `verified`, a
  derived OKF trust tier, or `usage_count`;
- `generated.at` records the last meaningful content change, which is not
  necessarily a collection timestamp;
- `status: stable` describes knowledge-document lifecycle, not confidence in a
  public observation. Omitting `status` is not neutral because OKF v0.2 defines
  an absent value as `stable`;
- `stale_after` requires a defensible absolute freshness policy, and recon has
  no universal one for heterogeneous public metadata;
- each OKF `sources[].resource` should identify a followable artifact or an
  explicit scope descriptor, while many retained DNS values are observations,
  not resources.

At this decision's 2026-08-13 acceptance date, Agent Plugins v1.0.0 was a
Working Draft for packaging skills and MCP servers. It does not define a
runtime evidence format and does not change the capsule decision. Version
1.0.0 is now Published, which does not alter this ADR's boundary.

## Decision

recon adds a separate observation-capsule contract with these boundaries:

- The artifact is versioned JSON with its own Draft 2020-12 schema. It does not
  add fields to or replace the stable v2 lookup JSON contract.
- A capsule records the collection window, frozen `as_of`, caller-supplied
  vantage label, collection options, cache provenance, per-source opportunity
  states, retained normalized facts, the normalized snapshot, stable signal
  identifiers, software and normalizer versions, catalog and model digests,
  and a deterministic SHA-256 content digest generated by recon.
- Replay is local and performs no network calls. It verifies the capsule and
  projects the recorded normalized snapshot through the installed renderer.
- Comparison emits separate observation, collection-regime, time-evaluation,
  and interpretation sections. A source role that is unavailable or partial at
  either endpoint cannot produce a confirmed addition or removal.
- Capsules remain local and caller-owned. recon does not add monitoring,
  longitudinal retention, upload, or hosted storage.
- The digest detects accidental or unkeyed content modification. It is not a
  signature, identity assertion, or proof of authenticity.

An OKF v0.2 projection is deferred because there is no named consumer. A future
proposal must identify that consumer, map every populated field without
upgrading a claim, include a privacy review, keep the capsule and stable recon
JSON authoritative, and independently validate the resulting OKF bundle.
`verified` and `stale_after` must remain absent unless their exact semantics are
established. The proposal must also establish lifecycle semantics for every
concept because an omitted OKF `status` defaults to `stable`; omission cannot be
used to avoid that assertion. It must not translate recon rule-review dates,
fingerprint confidence, or aggregate occurrence counts into OKF verification,
trust, or usage. The OKF projection, if later justified, is additive.

Agent Plugins packaging remains the separate v2.15 decision. No capsule command
or file claims Agent Plugins conformance.

## Consequences

- A caller can preserve and compare evidence without creating a project-run
  retention service or silently changing the existing lookup schema.
- Role-level suppression is deliberately conservative. A partial aggregate
  source role may withhold more fact deltas than a future channel-level
  opportunity model, but it cannot turn failed collection into an asserted
  change.
- Capsule schema v1 records explicit time-evaluation changes. Its
  `freshness_changes` array remains empty until a stable claim family has an
  absolute, replayable freshness predicate. The implementation does not invent
  a universal time-to-live value.
- Retained public DNS records and verification tokens may still be sensitive in
  an operator's context. Documentation must tell callers to protect capsule
  files and review them before sharing.
- OKF and Agent Plugins stay visible in the roadmap without premature
  conformance or export claims.
