# recon catalog maintenance

Use a recon source checkout. Read `AGENTS.md`, `CONTRIBUTING.md`, and
`docs/catalog-maintenance.md`; resolve paths from that checkout. PyPI supplies
the ordinary CLI and MCP server, not these maintainer helpers. This entry point
works as plain instructions in any compatible harness and needs no paid model.

Start with the offline example:

```text
uv sync --locked
uv run python -m validation.catalog_maintenance demo
```

Keep private inputs and all outputs in the ignored roots named in the guide.
Never commit or upload membership, raw observations, per-domain rows or opaque
values. A hash is not anonymization. Use explicit reviewed public file lists
and the canonical hygiene gate before proposed commits or uploads.

Choose the requested mode, preserving existing authorization:

| Mode | Canonical next step |
| --- | --- |
| Documentation only | First-party source review and monthly due/review receipts; no target collection |
| Existing local artifacts | `recon-fingerprint-triage` and the typed baseline; unavailable is not empty |
| Private planning | `recon-corpus-plan`, then freeze the maintenance plan, source bytes, budgets and exclusions |
| Authorized collection | `recon-catalog-round` and explicit maintenance `collect --allow-network`; never infer authorization from a scheduled wake |
| Evaluation | Typed retained-result reduction, original round contract and any sealed one-use holdout; never auto-promote |
| Proposed PR | Disclosure-safe support, claim disposition, synthetic fixtures and full gate; reserve a proposal claim before an authorized external write |

Review atomic and structural/composite layers separately. State observed,
tested, unavailable, disabled and unreviewed scope. An atomic addition cannot
silently strengthen an inference claim. Structural changes need positive and
counterexample graphs/sequences, missing/failed sources, duplication and
appropriate permutation checks, bounded work, and human/JSON/MCP provenance.
Sequence order can be meaningful; do not demand invariance to reversed hops.

For private sampling, preserve source vintage, eligibility, actual exclusions,
caps and convenience-selection bias. Plan a bounded mix of geography/language,
defensibly known scale, sector/ownership, website role, provider mix and sparse
or rich footprints. Unknown stays unknown. Rank is not company size; ccTLD,
language and hosting location do not establish organizational geography. Count
namespaces and declared dependencies separately; publish no tiny subgroup rates.

Monthly wakes only reserve bounded due work. Record actual source checks and
next review, keeping completed, no-change, blocked, skipped and overdue states
distinct. Resume immutable submissions; reconcile an outstanding proposal with
GitHub before retrying it. No recurring job is activated by these instructions.

On interruption preserve the original run. Without durable item starts, retain
unknown starts rather than calling unfinished items unattempted. Declare a
separate budgeted retry. Never expand scope, overwrite failed results, refresh
unreviewed dates, or reduce publication thresholds to obtain a passing result.
